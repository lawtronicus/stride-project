# Working on Stride

Read [STRIDE_BIBLE.md](STRIDE_BIBLE.md) before planning or implementing changes. It is the source of truth for product direction and major technical decisions.

- Check changes against its opening checklist. Distinguish confirmed direction, current behavior, proposals, and open questions.
- Identify conflicts with documented commitments before changing affected behavior. Explicit new user decisions can supersede existing decisions; update the record alongside the implementation.
- Update the Bible when agreed product behavior or major technical decisions change. Do not turn proposals into requirements or invent rationale for existing implementation.
- Preserve training history, user isolation, and the distinction between original plans, revised plans, and actual activity.
- Follow the Bible's validation guidance and [GETTING_STARTED.md](GETTING_STARTED.md) for relevant setup. Use the existing checkout; do not create a Git worktree unless requested.
